# 实战记录 — 照着跑一遍就能验证环境

本文件是**验收标准**。每个 Agent 上手后应先用一张样例图纸跑通下面的流程，
输出与本文的「预期」一致，才算环境正确。

---

## 0. 环境准备

```bash
sh scripts/setup.sh .
```

**预期输出（末尾）**：

```
== 检查 Python 绘图库
   PIL 已装
   中文字体 ✓

✓ 环境就绪
  下一步：node .../inspect.mjs <图纸.dwg>
```

退出码应为 0。若报 `找不到 node`，先装 Node.js。

---

## 1. 体检

```bash
node scripts/inspect.mjs demo.dwg
```

**预期输出**：

```
──────────────────────────────────────────────────────────────
文件      demo.dwg
版本      AC1018   代码页 gb2312
实体      2254
图层      24
块        21  (被引用 1)
文字对象  56   其中含中文 28
──────────────────────────────────────────────────────────────
```

**判据**：

| 情况 | 结论 |
|---|---|
| `其中含中文 > 0` | 可翻译，继续第 2 步 |
| `其中含中文 = 0`，但实体多为 Line/LwPolyline | 文字已被炸成线条，**停手**，报告无法原地翻译 |
| 报 `does not support this version` | 走本技能（GDAL 只支持 AC1015，本工具支持 AC1018+） |

---

## 2. 生成翻译表

埃尔派图纸用官方词库：

```bash
node scripts/glossary2map.mjs references/alpa-glossary.json map.json --short
```

**预期**：

```
已生成 map.json（短称模式），共 113 条
  设备-主机: 22
  工艺环节: 10
  设备-辅助: 32
  管道与仪表: 14
  图框标题栏: 23
  技术说明: 12
  （其中 59 条无短称，已用全称）
```

其他厂商的图纸用 `references/glossary-cn-en.json`，或按 `{"中文":"English"}` 自建。

---

## 3. 翻译

```bash
node scripts/translate.mjs demo.dwg map.json demo-EN.dwg
```

**预期**：

```
改写 28 条，其中缩字高 4 条

已写出 ./demo-EN.dwg: 115029 字节, 头 AC1018
原图 AC1018 → 译文 AC1018
改动明细: ./demo-EN.dwg.log.json
```

**判据**：

- `改写 N 条` 应等于第 1 步的「含中文」条数；少则说明词表有遗漏
- 输出中若出现 `⚠ N 条未命中词表`，**必须补词后重跑**
- 输出中若出现 `⚠ 译文里仍有中文片段`，同样必须修
- 文件头必须与原图一致；不一致说明版本变了，需检查

---

## 4. 校验一：压线

```bash
node scripts/collide.mjs demo-EN.dwg demo.dwg
```

**预期**：

```
✓ 无新增压线

ℹ 另有 9 条原图就压线（与翻译无关）：
    ...

新增压线 0 条 | 原图固有 9 条
```

退出码 **0**。

**必须带原图参数**，否则无法区分「本次引入」与「原图固有」，结论会误导。
退出码 2 表示有新增压线，**必须处理后重跑**。

---

## 5. 校验二：结构完整性

```bash
node scripts/verify.mjs demo-EN.dwg demo.dwg
```

**预期（关键行）**：

```
图层     24 → 24 ✓
块       21 → 21 ✓
图层名   ✓ 全部保留
块名     ✓ 全部保留
...
残留中文  ✓ 0 条
──────────────────────────────────────────────────────────────
结论：通过
──────────────────────────────────────────────────────────────
```

退出码 **0**。任何一项标 `✗` 都不算完成。

**特别注意「图层名 / 块名 全部保留」**——如果出现 `?`，说明 GBK 补丁没生效
（`npm install` 覆盖了补丁），重跑 `python3 scripts/patch_acadts.py .`。

---

## 6. 预览（可选，但强烈建议）

```bash
node scripts/preview.mjs demo-EN.dwg preview.png
```

**预期**：`2200x1387  线=1983 文字=56` + `已生成 preview.png`

⚠ **预览用 PIL 渲染，字体与 CAD 实际字体不同**，可能出现文字粘连假象。
**以第 4、5 步的量化结果为准**，不要因为预览难看就判定数据坏了。

---

## 全部通过的判定

下面四条同时满足才算交付：

1. `translate` 输出「改写 N 条」= 含中文条数，且无未命中警告
2. `collide` 退出码 0（新增压线 0）
3. `verify` 退出码 0（结论：通过）
4. 输出 DWG 文件头与原图一致

## 常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `ERR_ENCODING_NOT_SUPPORTED: gbk` | Node 无 GBK 解码器 | 确认走的是 `cadkit.mjs` 加载的模块，别自己 `import` 库 |
| 图层名变 `????` | GBK 写出补丁未生效 | `python3 scripts/patch_acadts.py .` |
| `Cannot find package` | node_modules 不在当前目录 | 在装了依赖的目录下运行，或重跑 setup.sh |
| 改写 0 条 | 词表 key 与图纸文字不匹配 | 用 `inspect` 输出的原文精确对照，注意全角/半角标点 |
| 大批新增压线 | 用了全称而非短称 | 加 `--short` 重新生成 map |
| 中文变成一串乱码 | 用了错误的库（libredwg-web 字段名不同） | 本技能用 `@node-projects/acad-ts`，不要换成别的 |
